# Gallery Catalog — Profiles, Bar Presets, Widgets

> [!NOTE]
> **Archived document.** This catalog describes the 50 profiles from before
> the profile system was rewritten; those profiles are no longer under
> `presets/profile/` (the color palettes remain in `python/hyprsetup/themes.py`).
> For the sources and layout notes of the current profiles see
> [`preset-sources.md`](preset-sources.md); visual preview:
> [`preview.html`](preview.html) (generated by `./tools/preview.sh`).

Derived from the 43 reference images under `temaornek/` (29 rice screenshots +
14 video frames).

**Copyright note:** None of the source images (Reddit r/unixporn screenshots,
most of which contain copyrighted illustration/art) is included in the
repository, and none is copied directly as a wallpaper. Instead, for all 50
profiles there is a generated (procedural) image under
`wallpapers/<profile>.png` that evokes the source's *composition* but is
derived entirely from the palette — it is drawn from scratch by
`python/hyprsetup/wallpaper.py` according to `WALLPAPER_STYLE` and carries no
copyright risk. `WALLPAPER_IMAGE` copies this pre-generated file directly
instead of regenerating it during installation (see `install.sh:wallpaper_step`);
if the file is missing it automatically falls back to on-the-fly generation
from `WALLPAPER_STYLE`.

**Scope:** every reference image maps to a profile. If the source is not
Hyprland (i3, dwm, awesome, Xfce, KDE, GNOME, Cinnamon, niri) its equivalent is
built in Hyprland — see the §3a translation table.

The goal is not a pixel-perfect copy. In every profile these three must be
consistent with the source: window layout, color palette, bar layout.

The hex values here are sampled from the relevant UI region of the source
(not from the wallpaper); `themes.py` fine-tunes them for readability, minding
FG/SUBTEXT contrast.

## 1. Axes

Three independent selection axes:

| Axis | Variable | File | GUI section |
|---|---|---|---|
| Profile | `PROFILE` | `presets/profile/*.conf` | Profiles |
| Bar preset | `BAR_PRESET` | `presets/bar/*.conf` | Bar Presets |
| Widget | `WIDGETS` | `presets/widget/*.conf` | Widgets |

A profile provides **defaults** for the other two; if the user picks one
separately, the user's choice wins (see the `preset_apply` precedence rule,
`lib/preset.sh`).

Color always comes from `THEME`. Bar presets and widgets define no colors —
so every bar works with every theme.

## 2. Bar presets (15)

`presets/bar/<name>.conf`, plus, if needed, a `{{#if BAR_IS_<NAME>}}` block in
`templates/waybar/style.css.tmpl` (a single file, no separate `styles/`
subdirectory — `render.py:_bar_vars` generates a `BAR_IS_<NAME>` flag for each
preset).

### islands — Island/pill groups
Source: ambxst, hyprlust, lamp, kde-no-waifu, videoframe_690, videoframe_1184
Modules are split into 3-5 separate rounded islands; the bar floats. Presents
medium-to-high information density in groups.
```
BAR_POSITION=top  BAR_HEIGHT=36  BAR_MARGIN=8  BAR_SPACING=10
BAR_PADDING=12    BAR_RADIUS=14  BAR_OPACITY=0.92
BAR_MODULES_LEFT=hyprland/workspaces
BAR_MODULES_CENTER=mpris
BAR_MODULES_RIGHT=network,bluetooth,battery,tray,clock
```
Implemented: instead of Waybar's native "group" wrapper (more fragile with GTK
CSS), consecutive system modules (network…battery) are merged into a single
visual island via corner rounding + tight spacing, while the remaining modules
(workspaces, mpris, tray, clock) are separated into their own islands with
wide spacing — `window#waybar` is already transparent (the shared rule above).

### slim — Thin full width
Source: cosmic, mangowc, dwm-dune, i3-nord, sway, cinnamon, bluefin,
videoframe_1464, videoframe_2316, videoframe_1860
Edge to edge, no corners, the highest information-per-pixel ratio.
```
BAR_POSITION=top  BAR_HEIGHT=22  BAR_MARGIN=0  BAR_SPACING=6
BAR_PADDING=6     BAR_RADIUS=0   BAR_OPACITY=1.0
```

### outline — Outlined segments
Source: sway-monochrome
Modules have no fill; each sits on the same background as the bar but in its
own box with a 1-pixel outline. Separation comes from border lines, not
fills — a dwm/dzen legacy, a line-drawn look; especially legible on light
palettes. The active workspace is the only filled item here; otherwise you
cannot tell where the focus is.
```
BAR_HEIGHT=26  BAR_RADIUS=0  BAR_MARGIN=0  BAR_OPACITY=1.0
BAR_WORKSPACE_STYLE=occupied-only
BAR_MODULES_RIGHT=tray,network,pulseaudio,clock
```
Template work: the `{{#if BAR_IS_OUTLINE}}` block in `style.css.tmpl` undoes
the `background-color` from the shared rule and puts an outline in its place.

### rail-top — Left rail + top bar
Source: videoframe_2481 (mando), videoframe_1509 (alpine), niri-abomination
Difference from `rail`: the rail carries no information; the thin status bar
on top carries it, and the rail remains an app icon strip. All three
references above had a top bar **next to** the rail, and `rail` alone did not
produce it.
```
BAR_POSITION=top  BAR_HEIGHT=24  BAR_WIDTH=48  BAR_RADIUS=0  BAR_OPACITY=0.9
BAR_MODULES_LEFT=hyprland/workspaces,cpu,memory
BAR_MODULES_CENTER=mpris
BAR_MODULES_RIGHT=pulseaudio,network,battery,tray,clock
```
`BAR_POSITION` is `top` here on purpose: Waybar takes a two-element bar
**array**; the first element is the top bar carrying all module definitions,
and the rail is added as the second element with width `BAR_WIDTH`
(`render.py` → `BAR_MULTI`, `BAR_HAS_RAIL`). `dock` uses the same array
mechanism.

### rail — Vertical left rail
Source: niri-abomination, videoframe_0, videoframe_1141, videoframe_2481
An icon strip on the left edge; the clock is written vertically (line by line).
```
BAR_POSITION=left  BAR_WIDTH=44  BAR_MARGIN=0  BAR_RADIUS=0
BAR_MODULES_LEFT=hyprland/workspaces
BAR_MODULES_RIGHT=clock,tray,custom/power
```
Implemented: `BAR_POSITION=left/right` and `BAR_WIDTH` are translated into a
vertical config in `render.py:_bar_vars` via `BAR_SIZE_KEY`/`BAR_SIZE`.

### dock — Thin top bar + bottom taskbar
Source: nixos, ambxst, kde-nothingos, gnome-tokyo-night, cinnamon, gnome-warm,
hyperland-zepyx
A thin, cornerless top status bar. A thin `wlr/taskbar` (an icon row of open
windows) is also rendered along the bottom edge — in this case the
`config.jsonc` root is not a single object but a two-element Waybar bar
**array** (see §5 "the bottom bar of the dock bar preset is solved").

### telemetry — Dense telemetry
Source: cosmic, kde-minimal, videoframe_2322, videoframe_0(1)
Per-core CPU, network speed, temperature, disk — 12+ modules.
```
BAR_HEIGHT=24  BAR_RADIUS=0  BAR_SPACING=8  FONT_SIZE=9
BAR_MODULES_RIGHT=cpu,memory,temperature,disk,network,pulseaudio,battery,tray,clock
```
videoframe_0(1) is covered by the `BAR_POSITION=bottom` variant.

### ~~media~~ — removed
It was a copy of `islands` shrunk by a few pixels (36→34 height, 14→12 corner,
0.92→0.90 opacity), and since it was not in `BAR_STYLES` it did not even get
the island CSS: it came out looking like the default bar. The "now playing in
the center" intent is already covered by `CENTER=mpris` in the `islands`,
`stats-only` and `telemetry` presets; no profile used it.

So that old `settings.conf` files containing `BAR_PRESET=media` do not break,
the name is mapped to `islands` (see `lib/preset.sh:PRESET_ALIAS` and
`python/hyprsetup/presets.py:PRESET_ALIASES` — the two must be updated together).

### sharp — Sharp/technical
Source: cybrland, videoframe_1997 (NERV)
Radius 0, corner cuts, a single accent color, uppercase typography, a thick top
border. Technical/HUD style — medium information density, focused on core
telemetry (no tray/bluetooth).
```
BAR_HEIGHT=28  BAR_RADIUS=0  BAR_MARGIN=0  BAR_OPACITY=0.95
BAR_MODULES_LEFT=hyprland/workspaces
BAR_MODULES_CENTER=hyprland/window
BAR_MODULES_RIGHT=cpu,memory,network,clock
```

### bracket — Square-bracket segments
Source: hyprland-second-linux-rice
Module groups inside `[ … ]` brackets, with no background; the brackets are in
the accent color. dwm/bspwm-style, "tag"-focused, low information density —
it focuses on workspaces and skips system details.
```
BAR_HEIGHT=26  BAR_RADIUS=0  BAR_OPACITY=0.0  BAR_SPACING=12
BAR_MODULES_LEFT=hyprland/workspaces,hyprland/submap
BAR_MODULES_CENTER=hyprland/window
BAR_MODULES_RIGHT=clock
```
Implemented: GTK CSS does not support content generation with
`::before`/`::after` (tried it; Waybar threw "Invalid name of pseudo-class") —
instead, when `BAR_PRESET=bracket`, `render.py:_bar_vars` adds real
`custom/bracket-open`/`custom/bracket-close` modules at the start/end of each
zone (static `[`/`]` text, runs no command).

### minimal — Almost no bar
Source: awesome-paws, videoframe_1112
An ultra-thin or auto-hide-only bar; desktop widgets carry the information
load. Makes sense together with the `clock` widget.
```
BAR_HEIGHT=18  BAR_MARGIN=0  BAR_RADIUS=0  BAR_OPACITY=0.0
BAR_MODULES_CENTER=  BAR_MODULES_RIGHT=clock
```

### taskbar — Bottom taskbar
Source: xfce-metro
A classic desktop bar at the bottom: workspaces + tray. Classic desktop feel.
```
BAR_POSITION=bottom  BAR_HEIGHT=28  BAR_RADIUS=0  BAR_MARGIN=0
BAR_MODULES_LEFT=hyprland/workspaces
```

### pill-single — A single long capsule
Source: hyprlust (top bar), kde-no-waifu, evercal, videoframe_690
Difference from `islands`: it is not split into groups; all modules are inside
**one** rounded capsule, about 60-80% of the screen width and centered. Few
modules fit in a single capsule (if it fills up, the look falls apart) — the
lowest information density.
```
BAR_POSITION=top  BAR_HEIGHT=32  BAR_MARGIN=6  BAR_SPACING=14
BAR_PADDING=16    BAR_RADIUS=16 BAR_OPACITY=0.95
BAR_MODULES_LEFT=hyprland/workspaces
BAR_MODULES_CENTER=
BAR_MODULES_RIGHT=tray,clock
```
Template work: `window#waybar > box` has the single background; the modules
have no background of their own.

### corner-tray — Asymmetric corner layout
Source: kde-no-waifu, videoframe_1464, videoframe_1860
No bar background. Power/menu in the left corner, a tray cluster in the right
corner, and only a thin workspace indicator (dots or small labels) in the
center.
```
BAR_HEIGHT=26  BAR_MARGIN=4  BAR_OPACITY=0.0  BAR_RADIUS=10
BAR_MODULES_LEFT=custom/power,hyprland/window
BAR_MODULES_CENTER=hyprland/workspaces
BAR_MODULES_RIGHT=tray,pulseaudio,network,battery,clock
```

### stats-only — No workspaces
Source: gnome-paperwm-bluefin, videoframe_1112
No workspace indicator on the bar at all; only system/media info and the
clock. A "the bar informs, it does not navigate" approach that stays out of
the focused window's way.
```
BAR_HEIGHT=20  BAR_RADIUS=0  BAR_MARGIN=0
BAR_MODULES_LEFT=hyprland/window
BAR_MODULES_CENTER=mpris
BAR_MODULES_RIGHT=cpu,memory,temperature,pulseaudio,battery,clock
```

### glass — Frosted glass
**Not derived from a reference** — while every other preset is the measured
counterpart of a rice under `temaornek/`, this one is a pure style choice
from the modern glassmorphism trend (e.g. hyprland-glass, hypr-glass). No
profile uses it; it exists for users to pick directly. The actual blur comes
from `layerrule = blur`, and that rule applies to EVERY bar preset — this
preset's real difference is the trio of low opacity + large corners + a tall
bar.
Fully floating, heavily rounded corners, low opacity — combined with the
`layerrule = blur` Hyprland already applies to the waybar layer (see
windowrules.conf) it gives a real frosted-glass look. The active workspace
stands out with a subtle `box-shadow` glow.
```
BAR_HEIGHT=42  BAR_MARGIN=10  BAR_RADIUS=20  BAR_OPACITY=0.5
BAR_WORKSPACE_STYLE=pill-expand
```

## 2a. Sub-axes (no file cost, multiplies variety)

These are not separate bar presets but curated values of the existing `BAR_*`
variables. They combine with every bar preset, so 14 bars × 8 workspace styles
produce real variation.

### Workspace indicator — `BAR_WORKSPACE_STYLE` (8)

| Value | Look | Source |
|---|---|---|
| `numbers` | `1 2 3 4 5`, active one filled | tokyo-night (existing), i3-nord, mangowc |
| `dots` | `● ○ ○ ○`, active one a large dot | ambxst, videoframe_1464, videoframe_1860 |
| `pill-expand` | the active one widens horizontally | hyprlust, gnome-tokyo-night, videoframe_1184 |
| `underline` | fixed digits, the active one underlined | kde-minimal (`w1…w7`), cinnamon |
| `bracket` | inside `[ 1 2 3 ]` brackets | second-linux-rice |
| `occupied-only` | only occupied workspaces are listed | dwm-dune (`1 2 3 5 9`), videoframe_1112 |
| `app-icons` | window icons instead of numbers | cinnamon, gnome-paperwm |
| `named` | `desk / stuff / web / code` | gnome-warm-rice |

Implemented: all 9 styles are generated in `config.jsonc.tmpl` via
`BAR_WS_<NAME>` flags (branching on `format-icons`/`format`), and the ones that
need it get their visual counterpart in `style.css.tmpl`.

### Clock format — `BAR_CLOCK_FORMAT` (6)

| Value | Source |
|---|---|
| `%H:%M` | mangowc, dwm-dune, videoframe_1464 |
| `%a %d %b  %H:%M` | gnome-warm (current default) |
| `%H:%M:%S` | cybrland, videoframe_1509 |
| `%H:%M%n%A, %d %b` (two lines) | videoframe_690, cinnamon |
| `%d.%m.%Y %H:%M` | i3-miasma, videoframe_1509 |
| `%H:%M` + superscript seconds | videoframe_350 |

## 2b. HyprPanel bar presets (6)

`presets/bar/` holds 26 files in total: the 15 Waybar presets in §2 above + the
6 HyprPanel presets here + the 5 Quickshell presets in §2c. These only make
sense when `BAR="hyprpanel"` (for the dashboard/notification modules Waybar
has no equivalent of) — the 3 KDE/GNOME-sourced profiles in §3 use one of
them.

**Variety parity** is kept across backends: every backend has a plain / dense /
floating (dock) preset, and the GUI's "Bar Presets" page shows the presets
split into these three columns. Parity cannot be complete, because the
backends support different things: HyprPanel cannot draw a vertical layout
(top/bottom only), and Quickshell has eight modules and no system tray.

HyprPanel presets with `BAR_MARGIN > 0` (`hyprpanel-dashboard`,
`hyprpanel-media`, `hyprpanel-dock`) are generated with `bar.floating=true` —
HyprPanel only actually applies the margin while this flag is on
(`render.py:_hyprpanel_vars`); otherwise the preset would look different from
its Waybar counterpart.

### hyprpanel-dashboard
```
BAR_POSITION=top  BAR_HEIGHT=36  BAR_MARGIN=6  BAR_SPACING=10
BAR_PADDING=12    BAR_RADIUS=14  BAR_OPACITY=0.92
```
Left: dashboard + workspaces. Center: mpris. Right: notifications, volume,
network, battery, clock.

### hyprpanel-monitor
```
BAR_POSITION=top  BAR_HEIGHT=28  BAR_MARGIN=0  BAR_SPACING=6
BAR_PADDING=8     BAR_RADIUS=0   BAR_OPACITY=1.0
```
Dense system monitoring: weather, updates, network speed, microphone, CPU/RAM,
world clock, notifications — the highest information-per-pixel ratio.

### hyprpanel-minimal
```
BAR_POSITION=top  BAR_HEIGHT=30  BAR_MARGIN=0  BAR_RADIUS=0  BAR_OPACITY=0.95
```
Left: workspaces. Right: volume, battery, clock. The panel's menus (dashboard,
notification center) stay installed but take no room on the bar — the "I want
HyprPanel for its menus, not its bar" case.

### hyprpanel-media
```
BAR_POSITION=top  BAR_HEIGHT=38  BAR_MARGIN=8  BAR_RADIUS=18  BAR_OPACITY=0.88
```
Center: mpris. Right: cava, volume, notifications, clock. A floating bar; the
same visual family as Waybar's `islands`/`pill-single`.

### hyprpanel-dock
```
BAR_POSITION=bottom  BAR_HEIGHT=42  BAR_MARGIN=10  BAR_RADIUS=20  BAR_OPACITY=0.85
```
A floating panel on the bottom edge, with the `app-icons` workspace style.
Since HyprPanel does not support vertical layouts, "bottom" is this backend's
only real position alternative (see `_HYPRPANEL_VERTICAL_FALLBACK`).

### hyprpanel-stats
```
BAR_POSITION=top  BAR_HEIGHT=26  BAR_MARGIN=0  BAR_RADIUS=0  BAR_OPACITY=1.0
```
No workspace indicator; CPU, RAM, temperature, disk, network speed, pending
updates. The HyprPanel counterpart of Waybar's `stats-only` preset.

## 2c. Quickshell bar presets (5)

`presets/bar/quickshell-*.conf` brings a third **backend**.
When `BAR="quickshell-bar"`, `templates/waybar/*` is not generated at all; the
bar is drawn in `templates/quickshell/shell.qml.tmpl`. Five presets:
`quickshell-bar` (floating standard), `quickshell-minimal` (workspaces + clock
only), `quickshell-dense` (all eight modules, no corners),
`quickshell-dock` (a floating capsule at the bottom) and `quickshell-rail`
(vertical left rail).

Why it was added: quickshell and eww only produced **widgets** in this repo —
all panels in their templates had `exclusiveZone: 0` and were pinned to
corners, i.e. floating cards. The only backend where "bar and widgets are one
system" was HyprPanel, and that is a heavy package from the AUR. Quickshell is
a repo package and `shell.qml` already carried 15 widgets; the bar was just one
more `PanelWindow` with `exclusiveZone` set.

```
BAR="quickshell-bar"
BAR_POSITION=top  BAR_HEIGHT=34  BAR_MARGIN=6  BAR_RADIUS=12  BAR_OPACITY=0.9
BAR_MODULES_LEFT=hyprland/workspaces,hyprland/window
BAR_MODULES_CENTER=clock
BAR_MODULES_RIGHT=cpu,memory,pulseaudio,network,battery
```

* **Module lists are actually read.** `render.py:_quickshell_bar_vars` turns
  each zone into `QS_{L,C,R}_<NAME>` flags; the template only draws the ones
  that are set. Modules with a QML counterpart: `hyprland/workspaces`,
  `hyprland/window`, `clock`, `cpu`, `memory`, `battery`, `pulseaudio`,
  `network` (see `QS_BAR_MODULES`). A name without a counterpart — e.g. `tray`;
  writing an SNI client on the Quickshell side is a separate job — is silently
  skipped, exactly like Waybar's behavior.
* **One process.** The bar and the widgets share the same `shell.qml`; even if
  both are given to Quickshell, a single line is written to autostart
  (`render.py`, "quickshell -p ~/.config/quickshell/hyprsetup/shell.qml").
* **The difference from widgets is `exclusiveZone`:** the bar reserves space
  at the edge, so windows do not end up underneath it. Desktop widgets keep
  floating with `exclusiveZone: 0`.
* **The vertical rail is truly vertical.** With `BAR_POSITION=left/right`, the
  template builds the zones as a `Column` instead of a `Row`, the edges are
  anchored top/bottom instead of left/right, and the workspace dot grows its
  long side vertically — all of this comes from the `QS_ZONE`, `QS_START`,
  `QS_END`, `QS_CROSS`, `QS_WS_WIDTH/HEIGHT`, `QS_TEXT_MAX` variables in
  `render.py:_quickshell_bar_vars`. Before, a vertical position only narrowed
  the window and the modules were still laid out horizontally; that is why
  `quickshell-rail` only makes sense now.

## 2d. Terminal presets (5)

`presets/terminal/*.conf` — unlike bar presets these are **program
independent**: the same six keys (`TERM_OPACITY`, `TERM_PADDING`,
`TERM_FONT_SIZE`, `TERM_CURSOR_STYLE`, `TERM_CURSOR_BLINK`,
`TERM_SCROLLBACK`) are translated separately for kitty, foot, Alacritty and
Ghostty (`render.py:_terminal_vars`). Places that need translation:

| Setting | kitty | foot | Alacritty | Ghostty |
|---|---|---|---|---|
| Cursor shape | `block/beam/underline` | same | `Block/Beam/Underline` | `beam` → `bar` |
| Blinking | seconds (`0` = off) | `yes/no` | `Never/Always` | `true/false` |
| Scrollback | lines | lines | lines | **bytes** (lines × ~1 KB) |

Presets: `classic` (opaque, block cursor, 20k lines), `glass` (0.75 opacity,
18px padding), `compact` (9 pt, 2px padding, 50k lines), `readable`
(14 pt, 20px padding), `minimal` (2k lines, steady beam cursor).

## 2e. Launcher presets (5)

`presets/launcher/*.conf` — seven keys (`LAUNCHER_WIDTH`, `LINES`,
`POSITION`, `OPACITY`, `ICONS`, `ICON_SIZE`, `PROMPT`) are translated for wofi,
rofi, fuzzel and walker (`render.py:_launcher_vars`). Not all of them apply to
every program:

* **wofi / rofi** — all seven apply (rofi wants the position as a number:
  `center` → `0`, `top` → `2`).
* **fuzzel** — six of them, all except icon size; fuzzel derives the icon from
  the line height. Since it wants the width in CHARACTERS, the percentage
  value is passed through as a character count as is (the same ratio as the
  repo's old hard-coded value).
* **walker** — only opacity and icons. This repo does not generate walker's own
  configuration, only the theme CSS; width/lines/position stay at walker's own
  defaults.

Presets: `spotlight` (top, 55%, 6 lines), `centered` (centered, 45%, 10 lines —
the repo's old hard-coded values), `grid` (80%, 18 lines, 48px icons),
`minimal` (30%, no icons, `>` prompt), `glass` (0.70 opacity, 50%).

## 3. Profiles (50)

Each profile: palette + window layout + bar preset + widget suggestion +
wallpaper (`wallpapers/<profile>.png` — the source's real image, see the
copyright note above; otherwise a gradient/pattern derived from its palette).

`A` = light theme. `L` = layout.

**Waybar / HyprPanel split:** the 14 waybar presets in the Bar column (see §2)
— the profiles sourced from Hyprland/niri/i3/dwm/awesome/Xfce/mangowc all used a
plain info bar originally, so Waybar is already the closest match.

The 9 KDE/GNOME/Cinnamon-sourced profiles were first all assigned to HyprPanel
wholesale ("the source was a desktop environment, so it must want a
dashboard"). Going through the reference images one by one showed this was
right for only **3** of them; the other 6 had no dashboard/quick-settings panel
on screen, just a plain Waybar bar, and the profiles' own `desc:` lines already
described exactly that (e.g. slate-arch: "asymmetric corner bar with no
background"). These 6 were moved to the waybar preset the source really
shows — as a side benefit they also got rid of the `ags-hyprpanel-git` (AUR)
dependency.

The value `BAR="hyprpanel"` comes not from the profile but from the bar preset
itself (see presets/bar/hyprpanel-*.conf → `BAR=`); GUI gallery cards mark it
with a "Requires HyprPanel" badge.

**Note:** HyprPanel requires the `ags-hyprpanel-git` (AUR) package — if you
pick one of these 3 profiles and only generate the configuration without
installing packages (`--configs-only` / `--reapply`), the render stage skips
HyprPanel as "package not installed" and that profile's bar is never generated;
first run a normal installation (including packages) with
`./install.sh --preset <name>`.

**Fixed — `dotfiles/` was generated with the wrong backend.**
`tools/build-dotfiles.sh:resolve_primaries` unconditionally assigned the first
component in the package profile to every single-choice category; even if the
preset said `BAR="hyprpanel"`, `waybar` was written over it. Result: the ready
files of the three profiles using hyprpanel came out with a waybar
configuration (`dotfiles/warm-amber/waybar/`, `exec-once = waybar`). Second
defect: since the requested backend was never added to `SELECTED`,
`HAS_<NAME>` was not written and the template's `{{! require: … }}` line skipped
the file. Now the preset's choice is kept and the component is carried into
`SELECTED` — `dotfiles/warm-amber/` produces `hyprpanel/config.json` +
`exec-once = hyprpanel`.

| Profile | Source | HyprPanel preset | Why HyprPanel |
|---|---|---|---|
| `sunday-gold` | kde-sunday | hyprpanel-monitor | KDE Plasma panel; a dense telemetry strip with CPU/memory/disk/network on the left and media controls in the center |
| `vapenation-slim` | kde-plasma-minimal | hyprpanel-monitor | KDE Plasma panel; weather + CPU/RAM/GPU/battery/power/network — the highest information-per-pixel ratio |
| `warm-amber` | gnome-a-warm-rice | hyprpanel-dashboard | A GNOME Quick Settings panel left open on screen (Wi-Fi/Bluetooth/Power/Night Light tiles) |

The 6 profiles moved from HyprPanel to waybar:

| Profile | Source | New bar preset | What the image shows |
|---|---|---|---|
| `slate-arch` | kde-no-waifu | corner-tray | No bar background; power in the left corner, a single expanding pill in the center, a tray cluster on the right |
| `bluefin-moss` | gnome-paperwm-bluefin | stats-only | No workspace indicator on the bar at all; window title on the left, dense telemetry on the right |
| `nothing-mono` | kde-plasma-nothingos | dock | Thin top bar + a separate app dock on the bottom edge |
| `tokyo-dock` | gnome-tokyo-night | dock | GNOME dash: thin top bar + bottom app dock |
| `cinnamon-night` | cinnamon-i-cooked | dock | The Cinnamon pair: top applet bar + bottom taskbar |

## 4. Widgets (21)

Decision: **standalone widgets only.** Complete shells (noctalia, end-4,
caelestia) are out of scope — they impose their own bar and launcher, so they
did not combine with the bar gallery.

Consequences:
* There is no longer such a thing as a bar preset ↔ widget conflict; all three
  axes are truly independent. No section in the GUI gets locked.
* In return, nothing comes ready-made from upstream. "Reuse what exists" now
  applies at the **widget level**, not the shell level: individual widgets are
  adapted from eww community configs (mostly MIT/GPL). Each widget's license
  and source are written in the header of `presets/widget/<name>.conf`.
* HyprPanel stays an option in the `bar` category (it really is a panel); it
  is not part of the widget axis.

Every widget works with every bar and is selected individually. `WIDGETS` is
multi-select.

### Switching compatibility

To keep values from the previous preset from leaking when switching between
presets:

* **Ownership lists.** `presets.BAR_KEYS` / `LOOK_KEYS` (Python) and
  `PRESET_BAR_KEYS` (bash) define which settings a bar preset and a profile
  own. When switching presets these keys are first reset to their defaults,
  then the new preset's values are written. So if the new preset does not
  define a key, the default applies, not the old preset's value.
  Concrete example: `rail`'s two-line clock (`%H%n%M`) and its empty center
  zone no longer linger after switching to a horizontal preset.
* **User values are preserved.** The reset looks at `_PRESET_USER_KEYS` (bash)
  and, in the GUI, only at the keys of the relevant axis; values the user gave
  via `--set` or by hand are not overwritten, and changing the bar preset does
  not touch the theme/layout.
* **Zones left empty on purpose.** `lib/config.sh` uses `=` instead of `:=` for
  the module lists. `:=` treated the empty string as "not given" and wrote the
  default back; yet a vertical bar not wanting a window title is a meaningful
  choice. Until this was fixed, the shell and the GUI gave different results.
* **The widget engine is selected automatically.** When a widget is turned on
  in the GUI and no engine is selected, `eww` is selected too, and released when
  the last widget is turned off — so that "I turned the widget on but it does not
  show" cannot happen.
* **Validation extended.** `config_validate` now accepts the `left`/`right`
  positions and the nine workspace styles, checks `BAR_WIDTH` as a number and
  catches an unknown `BAR_PRESET` name. Before this fix, the 6 profiles using
  `rail` made the installation fail.

* **The bottom bar of the `dock` bar preset is solved.** The Waybar config now
  produces a bar **array** when `dock` is selected (`BAR_HAS_DOCK`, render.py) —
  in addition to the main bar on top, a thin `wlr/taskbar` is rendered along
  the bottom edge. Previously only the top bar came out and the bottom dock
  never appeared; the 7 profiles using `dock` (ambxst-lava, nixos-lantern,
  hyper-olive, warm-amber, tokyo-dock, cinnamon-night, nothing-mono) therefore
  looked half-finished.

### Wallpapers

The source rices' wallpapers are copyrighted and cannot be distributed.
Instead, each profile generates an image from its own palette that evokes the
source's composition (`python/hyprsetup/wallpaper.py`). Eight patterns:
`waves`, `stars`, `orb`, `mist`, `grid`, `paper`, `solid`, `dunes` — the
profile picks one with `WALLPAPER_STYLE`.

* **No dependencies.** The PNG is written directly with `zlib`; no
  Pillow/ImageMagick needed. Generating 1920×1080 takes under half a second;
  files are 2-75 KB.
* During installation `wallpaper_step` (install.sh) generates it and writes it
  to `WALLPAPER_PATH`; hyprpaper and hyprlock already read from there. **An
  existing file is not overwritten** — a user who puts their own image there
  does not lose it with `--reapply`.
* By hand: `python3 -m hyprsetup wallpaper --theme X --style Y --out file.png`
* The desktop mockups in the GUI (`DesktopPreview`) now draw the real
  wallpaper instead of a gradient; the generated image is cached per
  theme+pattern. Gallery cards use `use_custom_wallpaper=False`: if the user
  had their own wallpaper, all 48 cards would show it and the profiles could
  not be told apart.

**`dotfiles/` is up to date.** All 49 presets were regenerated with
`./tools/build-dotfiles.sh`, and `--check` reports all of them as "up to date".

**Scope note.** `dotfiles/` once covered only the 7 "vanilla" theme profiles
and the script carried a warning against being run without arguments; today
the directory holds all 49 presets (including the gallery profiles), so
running it without arguments is the expected behavior. `dotfiles/README.md`
was corrected accordingly.
